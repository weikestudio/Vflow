# Vflow 迭代候选清单（2026-10-23 调研 / 2026-10-24 第一轮落地）

市面同类项目调研 + 缺口分析。**这份文档只做判断，不等于要全做**——每项都标了成本和我的建议档位，等拍板。

> **第一轮已落地（2026-10-24）**：A 声音档案、E 复盘证据规则、F 版本约定、H 钩子库、I 敏感词表、K 二创边界本来就在；
> 这轮把"没闭上的三个环"补齐——**复盘闭环**（`review.py` + 待复盘队列）、**状态机单一真源**（三态 + 内容指纹、
> 模板与 skill 统一 schema）、**最后一公里质检**（`qc.py` 封面 + 成片），外加 **选题池**（`backlog.py`）、
> **环境自检**（`doctor.py`）、**回归测试**（`tests/`，含技能契约定位锁）。
> **第二轮（10-24 下午，V1.0）**：按新对标，把重心从"补环"转到"内容设计层 + 运营层"——
> 口播稿 V2（六模板 / 双钩子 / 可保存物 / 双轨）、内容策略 V2（双轨北极星）、复盘双轨 + 工作台表单、
> 小红书关键词矩阵 + AI 声明、声明台账、发布包、内容日历与系列化、发布队列（默认人工）、版本库。
> 下文保留原始判断，方便对照"当时怎么想的、后来怎么做的"。

## 一、竞品在做什么

| 项目 | 体量 | 它是什么 | 值得抄的点 |
|---|---|---|---|
| **Easel**（浙大 + 北大开源） | ~2000 star，114 个 skill | 社媒运营全链路工作台，五层闭环：发现 / 策划 / 创作 / 发布 / 归因。有 React Web 工作台 | 账号画像六维、热点雷达（聚合多平台热榜）、内容日历排期、一材多端适配、发布-数据闭环回写画像 |
| **video-autopilot** | ~2186 star | 长视频 + 竖屏 shorts 流水线，四模式：Plan / Build / Log Outcome / Optimize Patterns | **证据绑定**（声明必须有可验证依据）、**创作者声音档案**（写作前先读本人 2 篇同类型成稿）、**复盘不许因单条数据改默认** |
| **self-media-content-workflow** | 614 star，MIT | 中文自媒体 9 个 skill：趋势雷达、选题策略、平台文案、短视频制作、数据分析、微信发布 | 5 个人工确认点、**明确拒绝自动群发**（只产草稿或手动发布包） |
| **video-production-skills** | 11 个 skill | 素材索引 → 证据脚本 → 分镜 → 配音字幕 → 封面独立审查 → 成片质检 | 作者自己踩的坑："生成一堆文件分不清哪个是最终版""改两句话后面全得重来" → **版本与最终版标识**；封面单独一道审查 |
| **ecommerce-video-skills** | 12 个 skill | 一张图 → 15 秒竖屏带货片，storyboard.json 驱动，ffmpeg 出片 | **钩子 9 种类型**可直接检索、**广告法禁用词自检**、多平台尺寸导出（含安全区） |
| **Trend Catcher** | 单个 skill | 热点内容改写助手 | 风格卡锚定、七维拆解、**合规复制（借结构不借句子）**、强制审计（重复度 / 限流 / 同质化 / 广告法词） |
| **media-render-pipeline** | 单 skill | 从原始素材到成片：transcribe → pack → EDL → render → verify → iterate | render→verify→**iterate 自检循环**；子代理协议（隔离上下文、只回持久结论） |

**一句话总结竞争格局**：大家都在从"帮你写一条"往"帮你运营一个账号"走——画像、热点、日历、复用、数据回流，这五件事是新的分水岭。Vflow 现在还是一条**单条内容的流水线**，链路是通的，但缺"持续运营层"。

## 二、缺口清单

### A. 创作者声音档案（voice profile）✅ 已落地 2026-10-23

- **对标**：video-autopilot 的 creator voice profile；Trend Catcher 的风格卡
- **现在缺什么**：profile.md 里"语气"只有几条规则（说人话、先给结论、禁用词）。规则描述 ≠ 真实文风。模型照规则写，写出来还是"像 AI 写的那个人"，不是本人
- **补上后**：`$VFLOW/assets/voice-samples/` 放 2–3 篇自己写过的成稿（口播稿 / 小红书正文）。写剧本和文案前**先读样本**，对齐句长、断句节奏、口头禅、举例方式
- **成本**：低。改 profile 模板 + 在 vflow-script / vflow-package 加一步"读样本再写"
- **建议**：**做**。这是解决"AI 味"最便宜的一招，比逐条加规则有效得多

### B. 选题池 + 热点雷达（本地池 ✅ 已落地 2026-10-24；热点雷达仍暂缓）

- **对标**：Easel 热点雷达、self-media 趋势雷达、Trend Catcher
- **现在缺什么**：Vflow 选题是**被动的**——你给一个想法，它判断做不做。没有"主动挖选题"的能力，也没有"待做选题池"。结果就是每次开工面对空白页
- **补上后**：`$VFLOW/backlog.md` 选题池（状态：候选 / 在做 / 已毙，每条带"为什么毙"）。可选外挂：联网抓热榜/竞品更新，按 profile 受众筛
- **成本**：分两半。**选题池纯本地，成本极低**；热点雷达要联网抓取，中等且可能踩平台 ToS
- **建议**：**先做本地选题池**（几乎零成本，立刻能用）。热点雷达**暂缓**，等你真觉得选题不够用了再说——常见情况是选题太多做不完，不是没选题

### C. 一稿多端复用（repurpose）⏸ 仍未做

- **对标**：Easel 的"一材多端适配"
- **现在缺什么**：一条内容做完就完了。没有"这条视频 → 小红书图文 → 公众号文章 → 音频版"的复用链路，也没有跨项目的素材索引
- **补上后**：一条主线产出多形态；旧稿可检索可重组
- **成本**：中。要定义母版格式和每个端子的转换规则
- **建议**：**按账号定位判断**。如果内容资产是要长期复用的（比如 AI Skill 方法论系列），这个价值很高；如果只是追流量，优先级往后放。内容工程那一块的现成方案已经不少，可以先不重复造

### D. 跨项目资产库⏸ 仍未做

- **对标**：Easel 项目归档；video-production-skills 素材索引
- **现在缺什么**：`$VFLOW/assets/` 只有字体、BGM、封面模板。**没有内容级资产**：验证过好用的钩子、金句、案例、翻车记录、已拍素材
- **补上后**：写新稿时能检索"我之前哪条用过这个例子""哪个开头完播高"
- **成本**：低-中
- **建议**：**做一半**——先把"已验证钩子库"建起来（见 H），完整资产库等复盘数据攒够再说，没数据就是空库

### E. 复盘的证据规则✅ 已落地 2026-10-23

- **对标**：video-autopilot 的 Optimize Patterns 模式
- **现在缺什么**：vflow-review 能归因，但没有**规则约束**。容易一条数据爆了就改默认，一条扑了就推翻方法
- **补上后**：硬规则写进 skill——① 单次结果不能变成通用默认；② 只有**重复出现的可比证据**才能改 profile；③ 改必须可逆、要写明改了什么和因为哪几条数据
- **成本**：低。就是往 vflow-review 里加一节规则
- **建议**：**做**。profile.md 第 8 节"积累区"现在太空，这套规则正好补上。而且这条对外讲也很有说服力（"我不因为一条数据改方法"本身就是专业感）

### F. 版本与最终版标识✅ 已落地（final-* 指针 + 三态状态机）

- **对标**：video-production-skills 作者的踩坑记录
- **现在缺什么**：改稿后 `03-script.md` 直接覆盖，没有版本；`output/` 里多个成片分不清哪个是交付版
- **补上后**：约定 `03-script.md` 为主版本 + `drafts/` 存过程稿；`output/` 里 `final-*.mp4` 是唯一交付指针；改上游时提示下游哪些要跟着动
- **成本**：低
- **建议**：**做**。纯约定，不写脚本也能执行。你现在项目少感觉不到，攒到 20 条就会乱

### G. 成片自动质检✅ 已落地 2026-10-24（`qc.py video`，另加封面 `qc.py cover`）

- **对标**：media-render-pipeline 的 verif
- **现在缺什么**：vflow-produce 有 `validate_project.py` 只校验工程结构。成片本身没自检：字幕有没有超框、时长对不对、有没有黑帧静音段、音画同步没有
- **补上后**：出片后跑一遍 ffprobe 检查，不合格标出来重渲
- **成本**：中（要写检测脚本）
- **建议**：**暂缓**。出片量小的时候，人工看一眼比写脚本快。等批量出片再补

### H. 钩子库✅ 已落地 2026-10-23

- **对标**：ecommerce-video-skills 的"3 秒钩子 9 种类型"
- **现在缺什么**：vflow-package 只讲原则（"前 3 秒是生死线"），没有可检索的具体类型
- **补上后**：一份钩子类型清单（反常识数字、反问、场景代入、翻车预告、对比、悬念……），每种带例句和适用内容类型。写开头时直接从库里挑
- **成本**：低
- **建议**：**做**。便宜、立刻能用，而且攒着自己用过的钩子效果数据后，会变成真正的资产

### I. 本地敏感词 / 广告法词表✅ 已落地 2026-10-23

- **对标**：ecommerce-video-skills 广告法自检；Trend Catcher 强制审计
- **现在缺什么**：vflow-check 三层检查靠模型判断"平台机器可能识别什么"。没有本地词表兜底，模型漏了就是漏了
- **补上后**：一份可维护的词表（广告法禁用词 + 平台高频敏感词 + 你自己踩过的词），检查时先过词表再过模型
- **成本**：低-中（词表要持续维护）
- **建议**：**做**。这是硬需求，且是"检查阶段"最有说服力的部分。注意：词表只做自查提示，不做屏蔽词过滤——平台规则会变，别假装能穷举

### J. 系列化 / 内容日历⏸ 仍未做

- **对标**：Easel 内容日历；self-media 内容策略
- **现在缺什么**：Vflow 是单条流水线，没有"这 5 条是一个系列"的概念，也没有排期
- **补上后**：能把一个主题拆成系列，排期发布，系列内部互相引用
- **成本**：中
- **建议**：**暂缓**。账号还在找方向，系列化是方向定了之后的事。硬排期反而会逼你发不够好的内容

### K. 二创边界规则✅ 已落地 2026-10-23

- **对标**：Trend Catcher 的"合规复制"：借结构、节奏、角度，换案例、换视角、换表述
- **现在缺什么**：vflow-topic 讲了"抄机制"（具体到秒到句），但没讲清楚**边界在哪**——什么能借、什么必须换、相似度怎么自检
- **补上后**：明确规则 + 一条自检项（改写后是否与原句高度相似）
- **成本**：低
- **建议**：**做**。防风险，而且这是你"对标三层筛"方法论的完整闭环（能学 → 能抄 → **抄到什么程度算越界**）

### L. 子代理协议⏸ 仍未做

- **对标**：media-render-pipeline 的 worker 协议
- **现在缺什么**：长链路跑下来上下文会膨胀，尤其是 produce 阶段
- **补上后**：约定哪些活派给子代理、子代理只回持久结论（改了哪些文件、关键时间码、阻塞点），不把过程倒回主上下文
- **成本**：低（纯约定）
- **建议**：**暂缓**。等你真遇到上下文不够用再说，现在加了也是空规则

## 三、第一轮实际做了什么（2026-10-24）

按"先补没闭上的环、再加宽"重排。原计划里的低成本项大多已在 10-23 落地，这轮真正动手的是：

| 优先级 | 做了什么 | 落在哪 | 解决什么 |
|---|---|---|---|
| P0 | **复盘闭环** | `scripts/review.py`、工作台「待复盘」 | 复盘 0/15 次的历史；资产层空转 |
| P0 | **状态机单一真源** | `scripts/vflow_state.py` 重写、模板按 skill schema 重写 | 状态和磁盘不一致、模板两套写法 |
| P0 | **最后一公里质检** | `scripts/qc.py`（封面 + 成片） | 封面糊、黑帧、静音、响度不够没人拦 |
| P0 | **回归测试** | `tests/runner.py` + `run_regression.sh` | 改 skill 改坏了没人知道 |
| P1 | **选题池** | `backlog.md` + `scripts/backlog.py` | 每次开工面对空白页 |
| P1 | **环境自检** | `scripts/doctor.py` | 换机器 / 新装不知道缺什么 |
| P0 | **口播稿 V2** | `assets/structures.md`、`vflow-script`、`script_check.py` | 结构靠手感、开头慢热、没有可保存物 |
| P0 | **内容策略 V2** | `docs/content-strategy.md`、`profile.md` | 指标口径停在 2024（完播为主） |
| P0 | **复盘双轨 + 表单** | `review.py`、工作台回填 | 收藏率/复访没进指标，复盘靠命令行 |
| P0 | **小红书关键词矩阵 + AI 声明** | `vflow-package`、`qc.py package` | 搜索流量吃不到，AI 声明缺失 |
| P0 | **声明台账** | `scripts/claims.py` | 数字没溯源，"可信"没有检查点 |
| P0 | **发布包** | `scripts/package.py` | 发布摩擦高，每周 2 条难稳定 |
| P1 | **内容日历 + 系列化** | `content_calendar.py` | 没有复访设计 |
| P1 | **发布队列** | `publish.py` | 默认人工，半自动辅助 |
| P1 | **版本库** | `VERSION`、`versions/`、`version.py` | 改了什么没人记得 |

**仍然没做**：热点雷达（ToS 风险 + 当前不缺选题）、一稿多端（先看内容资产是否值得复用）、
完整跨项目素材库（没数据就是空架子）、子代理协议（上下文还没吃紧）。

下一轮再看什么：先把 V1.0 用满 10 条真实内容，每个轨道攒够 3 条复盘，
再决定要不要碰一稿多端（C）和素材库（D）。**没有数据支撑的扩宽都是空架子。**

## 四、还需要你定的两件事

1. **Vflow 要不要往"账号运营"走？** 现在它是单条内容流水线。竞品已经在做画像 + 热点 + 日历 + 数据回流。往那边走意味着 scope 变大很多，但也可能更有产品力。**我的倾向是暂时不往那边扩**，先把单条链路做到别人抄不走（差异化在"能带走"和跨平台，不在功能多）
2. **要不要保留"不自动发布"这条克制？** self-media-workflow 明确写了"绝不自动群发"。Vflow 现在也没有自动发布。我建议**保留**——这既是安全边界，也是对外讲的时候一个可信赖的差异化点
