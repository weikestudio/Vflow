# 内容策略（V1.0 · 2026-10）

> 这是账号的"作战地图"。`profile.md` 回答"我是谁、给谁看"，这份文件回答
> "怎么衡量、怎么排、怎么复盘、哪些是红线"。
>
> **口径提醒**：下面所有平台权重、阈值都来自公开报道和第三方整理，**平台没有公布完整算法**。
> 它们只用来定方向，不拿来当精确公式。真正的判据是你自己后台的历史中位数。

---

## 一、北极星指标（双轨）

Vflow 做两类内容，用两套指标，**不放在一起比**。

| | **深度轨**（信任 + 搜索） | **发现轨**（流量 + 破圈） |
|---|---|---|
| 主平台 | 小红书 | 抖音 |
| 内容类型 | B 拆解型、T3/T5/T6 模板 | T1/T2 模板、A 演示型 |
| 时长 | 90–180 秒 | 45–90 秒 |
| **第一指标** | **收藏率**（收藏 / 播放） | **5 秒留存** |
| 第二指标 | 搜索来源占比、复访率 | 完播率 |
| 互动指标 | 关注转化 | 评论率 |
| 点赞 | 参考，不作为目标 | 参考，不作为目标 |
| 达标参考 | 收藏率 ≥ 3%（方法类）/ ≥ 1.5%（观点类） | 5 秒留存 ≥ 45% |
| 不合格参考 | 收藏率 < 1% | 5 秒留存 < 30% |

**为什么不是完播率**：2026 年第三方整理的抖音权重是
**收藏率 > 复访率 > 铁粉互动率 > 5 秒留存 > 完播率 > 评论 > 点赞**，
考察窗口从 24 小时拉长到 7 天。方向很明确：平台在奖励"值得被存下来、还会回来看"的内容，
不是"让人看到最后"的内容。完播率降为诊断指标——它低说明结构有问题，但高也不保证有流量。

**小红书**：搜索流量占比持续上升（第三方口径约 35%，标题党说法有「逼近 50%」），
搜索排名看点击率、互动、有效停留、语义匹配。深度轨的核心是**能被搜到，且搜到之后有用**。

**基线怎么建**：不要横向比别人的数字。取你**过去 20 条**同轨道内容的指标中位数当基线，
新内容稳定高于基线才算进步。样本少于 3 条时，任何结论都只是猜测。

## 二、两个平台的角色

| | 抖音 | 小红书 |
|---|---|---|
| 角色 | 发现：让不知道你的人看到你 | 搜索 + 信任：让正在找答案的人找到你 |
| 流量来源 | 推荐为主 | 搜索 + 推荐 |
| 内容偏好 | 判断型、反常识、冲突 | 方法型、清单、可执行的步骤 |
| 标题 | 口语、带冲突、结果前置 | 前 20 字含核心搜索词 |
| 封面 | 大字压屏，一眼看懂 | 精致，可截图 |
| 正文 | 短，1–3 句 + 话题 | 可长，结构清晰、分段、关键词自然出现 |
| 发布后看什么 | 5 秒留存、完播、评论 | 收藏率、搜索来源、关注 |
| 风险 | 导流查得严 | 功效词、导流、AI 声明都要过 |

**一条内容两端分发必须改文案，不能一套粘贴两边。** 改的不只是标题——开头、例子密度、
结尾动作都要按轨道重写。

## 三、内容配比与节奏

| 类型 | 占比 | 目的 | 典型模板 |
|---|---|---|---|
| **判断型**（B 拆解，深度轨） | 40% | 立专业、建可信度、被收藏 | T1 / T2 |
| **方法型**（B 拆解 / A 演示，双轨） | 40% | 吃搜索、给动作、被复访 | T3 / T5 / T6 |
| **实录型**（C 实录） | 20% | 建信任、证明我在做 | T4 |

**起步节奏：每周 2 条**，一条判断 + 一条方法，交替；每月至少 1 条实录。
跑满 10 条拿到数据再谈加速——**没有数据支撑的加量只是更快地制造废稿**。

**系列化**：每 4 周一个主题月，同一主题下 3–5 条互相引用。系列的价值不是排期，
是**复访率**——观众看完一条会去找同系列的其他条。用 `scripts/content_calendar.py` 管理。

## 四、选题决策树

```
有想法
  │
  ├─ 1. 三问：能拿走动作？能证明我会做？三个月后有人搜？
  │      └─ 有一条 ❌ → 毙掉，写清原因进 backlog
  │
  ├─ 2. 平台上有人搜/看过吗？
  │      ├─ 小红书：有没有明确搜索词？（没有就换角度或换平台）
  │      └─ 抖音：同类内容数据能不能拆出机制？
  │
  ├─ 3. 可保存物是什么？
  │      ├─ B 拆解：判断标准 / 对照表 / 决策树
  │      ├─ A 演示：步骤 / 参数 / 可复用文件
  │      └─ C 实录：一个判断或动作
  │      └─ 说不出来 → 回选题，别往下走
  │
  ├─ 4. 我有什么别人没有的？（一手经验 / 翻车记录 / 更新数据）
  │      └─ 没有 → 只能做二创，按二创边界自检
  │
  └─ 5. 成本 vs 价值
         └─ 成本 > 价值 → 砍
```

## 五、可保存物（分类硬门槛）

2026 年收藏率是第一权重，所以可保存物不是"加分项"，是**入场券**。
但不能一刀切，按类型给不同标准：

| 类型 | 必须带走 | 没做到 |
|---|---|---|
| **B 拆解型** | 一条判断标准 / 一张对照表 / 一个决策树 | 不许进制作 |
| **A 演示型** | 一个能照做的步骤 / 一组参数 / 一个可复用文件 | 不许进制作 |
| **C 实录型** | 一个判断或一个动作（"我踩过这个坑，你别踩"也算） | 可以只给一个，但不能没有 |

**位置要求**：前 1/3 必须出现一次（让前 5 秒有东西可拿），结尾再收一次（让收藏有理由）。

## 六、小红书的搜索关键词矩阵

小红书的流量命脉是搜索。**标题即 SEO，正文即答案。**

**标题规则**
- 前 20 个字必须含核心关键词（搜索排名看 CTR，标题前 20 字是权重区）
- 用**长尾决策词**，不用大词：「油皮夏天控油水乳怎么选」>「水乳推荐」
- 人群 + 场景 + 痛点组合，比如「10 人小团队 用 AI 写周报 靠谱吗」

**关键词矩阵**（每条笔记必须填满四维）

| 维度 | 放什么 | 例 |
|---|---|---|
| 核心词 | 1–2 个，标题前 20 字内 | AI 工具 / 企业 AI |
| 长尾词 | 2–3 个，人群 + 场景 + 痛点 | 小团队怎么选 AI 办公平台 |
| 问题词 | 1–2 个，观众原话问句 | 换 AI 工具要重讲业务吗 |
| 场景词 | 2–3 个，具体到工作场景 | 写周报 / 整理会议纪要 |

**正文规则**：前 3 段自然出现关键词（不要堆砌，语义匹配优先）；中间融衍生词；
结尾给行动词。**标签 5–10 个**，混核心词 + 场景词 + 账号词。

**搜索语义**：2026 年搜索算法从"关键词精确匹配"升级为"语义理解"。
堆词会被判低质，**把观众真正在问的问题回答清楚**才是正解。

## 七、复盘回路

1. **48 小时后回填**：`review.py fill`，按轨道填对应指标（发现轨填 5 秒留存 / 完播；深度轨填收藏率 / 搜索来源）。
2. **看同轨均值**：`review.py stats --track`，不和另一条轨道比。
3. **归因到步骤**：是选题、结构、剧本、包装，还是检查阶段出的问题。
4. **一次只改一件事**：单变量实验。改五件事就无法归因，等于白做。
5. **观察进台账**：三条可比证据才准改默认（`ledger.py promote`）。
6. **写回策略**：只有台账升级之后，才更新 `profile.md` 第 8 节和这份策略。

**反例同样值钱**：某个判断后来被推翻，记进 `ledger` 的"已撤回"，比记成功更有用。

## 八、合规与声明

| 项 | 规则 |
|---|---|
| **AI 生成声明** | 平台要求对 AI 生成/合成内容做标识。发布包里写清楚哪部分由 AI 生成（画面 / 配音 / 文稿），不确定就说明"AI 辅助" |
| **素材授权** | 用别人的画面、音乐、字体，必须确认可商用；不确定就换掉 |
| **免费边界** | 推荐工具先说免费到哪一步、哪部分要钱，再说推荐 |
| **极限词** | 最 / 第一 / 唯一 / 100% 等广告法高风险词，`qc.py` 会拦 |
| **联系方式** | 平台查导流，正文和画面都不要放微信、二维码、外链 |
| **数字与事实** | 每个对外数字登记到 `claims.md`，标来源、口径、核验日期 |

## 九、什么不做

- **不追点赞**：点赞权重最低，追它等于给最不值钱的指标打工
- **不追爆款**：一条爆了不代表方法对，可能只是运气
- **不自动群发**：发布默认人工，半自动和自动要显式开启，见 `publish.py`
- **不堆功能**：热点雷达、自动群发量、批量养号都不做——风险高且和"可信度"定位冲突
- **不发没有信息增量的内容**：宁可少发

## 十、这份策略怎么改

改之前先问三个问题：

1. 是**一条数据**让我想改，还是**三条可比证据**？
2. 改的是**判断**还是**措辞**？（措辞随时可改，判断要过台账）
3. 改完能不能**撤回**？（不能撤回的改动不要做）

改完记到 `versions/` 当前版本的"影响面"里，并把变更原因写清楚。
