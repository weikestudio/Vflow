# 阶段 7 · 复盘

**目的不是打分，是找出下一条能改的具体动作。** 写不出动作的复盘等于没写。

## 什么时候做

发布 **48 小时后**。太早数据没跑完，太晚记忆凉了。

```bash
python3 $VFLOW/scripts/review.py pending          # 谁该复盘了（含超期）
```

发布时就要登记，否则脚本不知道有这条：

```bash
python3 $VFLOW/scripts/review.py published <slug> --platform douyin
```

数据回来了，一条命令回填，表、钩子、台账一起更新：

```bash
python3 $VFLOW/scripts/review.py fill <slug> --platform douyin \
  --play 12000 --ret5 45 --finish 28 --like 300 --comment 40 --save 120 --share 20 --follow 15 \
  --collect-rate 2.7 --revisit 18 --track 发现轨 \
  --good "开头具体痛点留人" --bad "第 6 页方法堆太多" --comments "有人要模板" \
  --action "下一条方法页压到 3 页"
```

它会自动：写 `06-review.md` 的数据表和判断、算互动率、把数据存进 `.vflow.json`、
把复盘阶段标成完成。**观察不自动进默认**——要进台账就加 `--observation "..."`，
或者单独跑 `review.py note <slug> "观察"`。

小红书多填一个 `--search-share 35`（搜索来源占比），判断长尾有没有起来。

## 看数据先分桶

不同受众的内容不能横向比。按 profile 里的定位先分桶，桶内比：

- **专业向**（面向决策层、客户）：看涨粉质量、私信/咨询、完播。播放量本来就不会高
- **泛流量向**（面向普通观众）：看播放、5 秒完播、互动率

**跨桶比数据会得出错误结论。** 一条专业向内容播放 3000 但来了 2 个咨询，比泛流量 10 万播放有用。

## 双轨指标（不跨轨道比）

**发现轨（抖音）**

| 指标 | 说明什么 | 低了改哪里 |
|---|---|---|
| **5 秒留存**（主） | 开头钩子 | 回头改 `04-package.md` 的开头 3 秒；换钩子原型 |
| 完播率（辅） | 结构和节奏 | 回头看 `02-outline.md`：有页废话或方法页太多 |
| 互动率 | 有没有共鸣 | 回头看 `03-script.md`：没有具体一手经验 |

**深度轨（小红书）**

| 指标 | 说明什么 | 低了改哪里 |
|---|---|---|
| **收藏率**（主） | 有没有可保存物 | 回头看 `03-script.md` 的可保存物；`04-package.md` 的标题有没有给答案 |
| 搜索来源占比 | 关键词铺对没有 | 回头看关键词矩阵：核心词/长尾词/问题词/场景词 |
| 复访率 | 系列有没有形成 | 用 `content_calendar.py` 排系列，标题用同组词 |

**点赞不做目标。** 2026 年第三方整理的权重里它排最后，追它等于给最不值钱的指标打工。
**达标参考**：发现轨 5 秒留存 ≥45%；深度轨收藏率方法类 ≥3%、观点类 ≥1.5%。
**样本少于 3 条时只能当参考**，别急着改方法。

## 归因要具体到步骤

不要写"内容不够好"。写清楚是哪一步出的：

- 选题阶段：三问里哪一问其实没过但硬做了
- 结构阶段：转折点来得太晚 / 方法页超过 4 页 / 缺证据页
- 剧本阶段：念着卡 / 信息密度不均 / 没有一手经验
- 包装阶段：标题承诺与正文不符 / 开头 3 秒是自嗨
- 检查阶段：被限流了（看是不是机器风险没清干净）

## 写回 profile：得过台账这一关

**一条数据不是规律。** 完播高可能是选题好、可能是钩子好、也可能只是运气。所以观察不直接进 profile，先记进证据台账：

```bash
python3 scripts/ledger.py add "露脸开头的完播明显高" --slug 20261022-这条
# 下次又见到同样现象：
python3 scripts/ledger.py add x --slug 20261025-下一条 --again E1
# 攒够三条再升级：
python3 scripts/ledger.py promote E1
```

三条门槛：

1. 一条 = 候选，**不改任何默认**
2. 三条**可比**证据（同平台、同类型、同期）才能升级
3. 升级必须可逆——脚本会告诉你改了什么、因为哪几条、怎么撤回。出现反例就 `retract` 降级

不够三条时 `promote` 会**直接拒绝**，并告诉你还差几条。这不是啰嗦，是防止"一条爆了就改方法、下一条照抄就扑了"这个最常见的坑。

只有升级之后的结论才写进 profile.md 第 8 节积累区。写的时候越具体越有用：

- ❌ "讲 AI 的内容数据好"
- ✅ "开头给具体数字（不是'很多'）的拆解型内容，5 秒完播平均高 12 个点"

**钩子数据也要回填**，否则钩子库永远是空的：

```bash
python3 scripts/hooks.py fill H7 20261022-这条 --ret3 48 --finish 31 --verdict 有效
```

## 边界

**做**：回填 48 小时数据（`review.py fill`），把结果归因到具体步骤，写下一条改什么，观察进台账。

**不做**：不因为一条数据改 `profile.md`（要过证据台账，攒够三条可比证据才准）；不给内容打分；不做传播机制解读——"这条为什么火了"是另一类分析，本阶段只回答"下一条改什么"。

**单独被调用时**：没发布、没数据就没法复盘，别硬写。发布不到 48 小时，数据没跑完，等。

**越界信号**：想把一次的结论总结成通用规律——先过台账，一条数据不构成规律。
