- **日期**：2026-10-24
- **类型**：major
- **摘要**：首个正式版本。七阶段流水线 + 内容设计层 + 复盘闭环 + 最后一公里质检 + 日历系列化 + 发布队列

## 改了什么

### 一、流水线骨架（10-22 起）

- 七阶段：选题 → 结构 → 剧本 → 包装 → 检查 → 制作 → 复盘，每阶段一个 skill，产出必须落盘。

- 三个确认点（选题卡、结构框架、成片）、检查没过不许进制作。

## 为什么

Vflow 原来的强项是"方法论 + 落盘 + 可追溯"，弱项是"内容能不能留人"和"运营能不能持续"。
这轮对标市面产品后发现，分水岭已经从"能不能生成"变成"能不能稳定产出可被保存、可被搜索、
可被验证的内容"。所以补的是内容设计层（结构模板、留存、可保存物、钩子原型）、
搜索层（关键词矩阵）、验证层（声明台账、双轨复盘）和运营层（日历、发布包、发布队列）。

## 影响面

- **数据格式**：`.vflow.json` v2（stages 加 `manual / fp / doneFp`；`qc / scriptQc` 新字段；
  `published.*.track`）。旧文件可用 `vflow_state.py migrate --write` 平滑升级。
- **新数据文件**：`claims.md`、`calendar.md`、`publish.config.json`、`backlog.md`（均在 .gitignore 中）。
- **技能行为**：剧本阶段必须先选模板；B 拆解型没有可保存物不许进制作；
  检查阶段新增声明台账；发布默认人工。
- **破坏性变更**：`pipeline/03b-teleprompter.md` 已移到提示词模板 `skills/_shared/teleprompter-template.md`；
  新项目不再自动复制 03b。旧项目不受影响。
- **脚本重命名**：日历脚本叫 `content_calendar.py`，不叫 `calendar.py`——后者会遮蔽 Python 标准库。
